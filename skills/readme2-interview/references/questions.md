# Questions: types, order and linking

## Question types

| Type | Use | Example (developer interview) |
|---|---|---|
| Open | start a block, get the story | "Walk me through the day you split the harness out of the main project." |
| Probe / follow-up | get detail, elaboration, reflection | "What happened next?" · "How did you notice?" |
| Closed | fill a missing detail at the end of a funnel | "Was that before or after version 1.0?" |
| Very specific | one precise fact | "How many terminal windows were open that night?" |
| Confrontation | an answer conflicts with a source | "The git log shows the guard was added on the 23rd, two days before you say. What happened?" |
| Reflective reframe | sensitive moment | "What was going through your mind at that point?" rather than "Why did you do that?" |
| Closing | end of session | "What should I have asked you that I didn't?" |

Sources: open/closed/very specific (Macmillan); probes then closed (NN/g);
confrontation and closing (jamditis interview-prep); reflective reframe (Storii).

## Order inside a block: the funnel

Open question → probes → closed questions only for what is still missing. Broad first
avoids priming the answer and builds rapport. (NN/g)

Variants (Macmillan):
- **Inverted funnel** (closed → open): for a reserved interviewee who needs to warm up.
- **Tunnel** (same level throughout): for a series of facts, for example a list of
  dates or versions.

## Order of blocks

1. **One organising structure**, chosen in the guide: timeline, topic, key event, or
   hybrid. (Storii)
2. **Light to heavy.** Easy topics first; failures, conflicts and doubts once trust is
   established; alternate heavier and lighter moments. (Storii)
3. **Specific moments, not habits.** Each block opens on a dated moment taken from
   `01-sources.md`. (Teresa Torres)

## Linking blocks

- **Bridge questions** connect one block to the next instead of jumping in time.
  Example: "That supervisor removed the copy-paste. What did it break that you did
  not expect?" (Storii)
- **Follow the interviewee's thread** when they open a new theme, then come back to the
  plan. (Storii)
- **Flow over rigid order** when the conversation is working. (Storii)

## Conduct rules

- **One question per message.** Stacked questions get the last one answered.
- **Press once.** A vague answer ("a while ago", "a lot", "much faster") gets one
  follow-up asking for the date, the number or the name. Accept the second answer;
  record `[?]` if it is still vague.
- **Bring generalities back to the story.** When the interviewee drifts into "I usually…",
  wait for a pause, then return to the specific moment. (Teresa Torres)
- **Never ask what the sources already answer.** Use the source as the anchor and ask
  about what it cannot show: the feeling, the doubt, the decision, the mistake.
- **Never lead.** Do not put the answer in the question ("It must have been
  frustrating?"). Ask "How did that feel at the time?"
- **Declined = closed.** Record it under Off limits in `02-pre-interview.md`.

## Bad questions (never)

- "Tell me about your journey." (vague theme, stock answer)
- "What are the main features?" (the README already says it)
- "Was it hard and did you learn a lot?" (double, leading, closed)
- Any question already in `04-transcript.md`.
